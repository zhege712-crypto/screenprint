# 答辩 playbook：结构、追问、备份页、话术

配合 `screenprint-defense/SKILL.md` 使用；引擎（做页、动画、审计、打包）走 `screenprint`。

## 1. 先把"贡献"写成一句话

模板：**「在 ___ 条件下，我用 ___ 方法把 ___ 指标从 ___ 改善到 ___，代价是 ___。」**

写不出来就不要开始做页面。这一句会变成第 5 页和结论页的第一条。

## 2. 页面级证据规则

| 页面类型 | 必须包含 | 禁止 |
|---|---|---|
| 背景/问题 | 一张能被非同行看懂的图 + 一句问题陈述 | 大段文献综述 |
| 差距 | "现有方法不能做 X"，附 2–3 篇代表工作 | 贬低他人工作 |
| 贡献 | 三条 claim，每条后面跟一句证据与范围 | 空泛的"提出了一种新方法" |
| 方法 | 输入/输出/关键假设/一个设计选择的理由 | 只放公式不解释符号 |
| 实验设置 | 数据、划分、基线、指标、重复次数 | 只写"实验证明有效" |
| 主结果 | 主表/主图 + 显著性/重复性说明 | 只挑最好的一组 |
| 消融 | 去掉每个模块的影响 | 消融与主张不对应 |
| 局限 | 至少 2 条真实局限 + 触发条件 | "没有局限" |
| 结论/展望 | 3 条结论 + 2 条下一步 | 引入新的未验证数字 |

## 3. 备份页清单（8–15 页，全部隐藏）

| 编号 | 内容 | 被问到就跳 |
|---|---|---|
| B1 | 与最相关工作的差异对照表（方法/假设/指标） | "你的创新点是什么" |
| B2 | 问题形式化与符号表 | "把你的问题再说清楚" |
| B3 | 算法伪代码 / 系统架构细节 | "具体怎么实现的" |
| B4 | 主基线实现细节与公平性设置 | "为什么不用 XX 方法" |
| B5 | 额外基线结果（更强/更新的方法） | "和最新方法比呢" |
| B6 | 计算复杂度、内存、时延实测 | "跑得动吗" |
| B7 | 假设失效时的行为（边界/压力测试） | "假设不成立怎么办" |
| B8 | 超参数敏感性曲线 | "调参了吗" |
| B9 | 重复实验与置信区间 | "是不是噪声" |
| B10 | 泛化到其他场景/数据的结果 | "换个数据还行吗" |
| B11 | 失败案例与原因分析 | "失败过吗" |
| B12 | 复现所需的一切（环境/版本/脚本/种子） | "我想复现" |
| B13 | 数据标注/采集流程与伦理 | "数据哪来的" |
| B14 | 论文里没放的补充实验 | "还有别的实验吗" |
| B15 | 未来工作分解（3/6/12 个月） | "接下来做什么" |

## 4. 追问预案（按评委类型）

- **方法型评委**：问假设、问边界、问理论保证 → B2/B7，回答用"成立条件 + 失去条件时会怎样"。
- **实验型评委**：问基线、问公平、问显著性 → B4/B5/B9，先给数字再给口径。
- **工程型评委**：问复杂度、问部署、问数据 → B6/B13，给实测值不要给估计。
- **挑刺型评委**：问"这不就是 XX 吗" → B1，用一张对照表，承认共同点再指出差异。
- **放水型评委**：问未来工作 → B15，给分阶段计划，不要空谈愿景。

回答三段式：**结论（1 句）→ 证据（数字/图表）→ 范围（条件与局限）**，控制在 40 秒内。

## 5. 时间与点击

- 15 min：12–14 页主讲，3 页/2.5 分钟；20 min：16–20 页。
- 每页 ≤ 4 次点击；点击表与讲稿必须一致（用 `screenprint` 的 `pptx_probe.py` 核对）。
- 留 3–5 分钟缓冲；超时比讲得少更致命。

## 6. 排练清单

1. 一遍只讲内容，录音，回听是否每页一句话能说清；
2. 一遍只按点击走，不看稿，确认每页点击顺序记得住；
3. 一遍按"评委打断"模式：随机跳到任一备份页，再回到主线；
4. 一遍对着镜子/录像，检查是否在读屏幕而不是讲；
5. 上台前 10 分钟：只过贡献页、结论页、B1、B12。

- 主讲版 PDF + 全本 PDF（备份页要包含在全本里，主讲版不含）；
- `CUE_CARD` 里每行加一列"可能被问 → 跳 Bx"；
